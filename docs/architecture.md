# 技术架构

Ferry 是原生 SwiftUI 应用，支持 macOS 14+。本地预览版优先验证 Apple Silicon。

```text
SwiftUI AppModel → EngineRunner → 独立 ferry-engine 进程
                                  ↓
                     Device 只读接口 → go-mtpfs/mtp → libusb → USB
                                  ↓
                     transfer.Engine → Mac 独立任务目录
```

## 应用层

`Sources/FerryApp` 提供中英文连接引导、存储导航、原生 Table、多选、搜索、下载进度及错误展示。`AppModel` 在 MainActor 更新界面，USB 操作由串行 helper 执行；下载队列允许继续选择、追加任务和浏览缓存目录，新目录读取在完整文件之间安排。

### 本地工具导航

侧栏“本地工具”首次打开显示两列卡片首页，不默认进入某个工具。LocalTool 统一提供名称、用途说明和系统图标；新增入口沿同一列表扩展。卡片显示未开始、扫描中、处理中、停止中、扫描完成、处理完成、已停止或需要检查问题的状态；详情顶部提供“返回本地工具”和当前工具名称。

AppModel.selectedLocalTool 为可选值，nil 表示工具首页；页面切换保留当前工具或首页位置。各工具控制器仍由 AppModel 持有，返回首页、切换主页面以及重新进入详情均不重建控制器、不清除计划或取消任务，后台结束也不自动离开首页。任务运行时始终允许返回首页及重新打开运行中的工具，其他工具卡片显示等待并禁用；AppModel 同时校验入口，保持本地工具互斥。高频进度只驱动本地工具视图，不发布到手机列表根模型。退出确认与取消机制不变。

### 本地图片/视频日期修复

侧栏“本地工具”提供本机文件夹图片/视频创建日期修复，不发起 USB/MTP 请求、不提权。进入工具页取消尚未执行的自动连接，已有下载和连接仍遵循原生命周期。AppModel 持有独立 PhotoDateRepairController，切页保留扫描/修复进度，工具高频进度不发布到手机列表根模型；退出确认计入本地任务，确认退出取消剩余工作。

选择文件夹后后台扫描，先展示统计和最多 20 张的日期预览，点击“修复 N 个文件”才执行。图片和视频类型独立选择，默认均开启；不改文件名和格式，结果及进度统一按媒体文件计数，预览以图片/视频图标和来源区分。包含子文件夹、文件名补充和仅日期模式默认开启；“同时修复修改日期”默认关闭。修改选项清除旧计划并要求重新扫描，修复模式冻结于扫描计划。预览展示当前创建日期和目标日期，勾选同步修改时另显示修改日期变化；任一需要修复的日期不一致即列入计划。优先读取 EXIF DateTimeOriginal、OffsetTimeOriginal 和 SubsecTimeOriginal；ImageIO 通过只读文件描述符的 CGDataProvider/pread 读取元数据，禁用缓存且每文件最多读取 8 MiB，不解码像素或重编码。时区偏移优先，无偏移按扫描时的 Mac 当前时区解释；日期及闰日严格校验。

没有有效 EXIF 时可从文件名识别明确的年月日时分秒，例如 20130607_190722；20121209_015 的 015 作为编号，开启“仅恢复年月日”时按当日 00:00 处理，关闭则跳过。文件名推测在预览中标为不同来源；视频读取与归档/重命名共用的 MediaCaptureTimestamp.video：通过 AVFoundation 只读加载内嵌拍摄/创建元数据及系统支持的容器日期，排除 1904 等占位时间，不解码或转码。无有效视频元数据时沿用可关闭的文件名补充，例如 VID_20250704_005959；没有有效时间则跳过，不用文件系统日期猜测。图片与视频均无日期、无效日期和多个冲突日期不处理，不将任意数字视为 Unix 时间戳。格式识别复用 RemoteEntry 的图片和视频扩展名集合，不扩展 Swift/Go 媒体表。

仅扫描所选类型的普通图片/视频文件，跳过隐藏文件（包括 AppleDouble ._ 侧车文件）、符号链接、Finder 替身、硬链接、应用包和 Photos/iPhoto/Aperture 资料库；选择资料库或其内部目录时拒绝操作，不跨子挂载卷扫描。目录深度最多 128 层、图片和视频合计最多 1,000,000 项，仅为需要调整的文件保存计划。计划捕获输出根及各媒体文件的设备/文件标识、长度、修改时间、创建时间和状态改变时间；应用时重新核对，根或媒体文件发生变化则拒绝或跳过。每个路径组件使用根目录描述符相对 openat 并带 O_NOFOLLOW 打开，父目录被链接替换也不能导致越界修改。

默认使用与下载创建日期选项相同的 fsetattrlist(ATTR_CMN_CRTIME) 仅提交目标创建时间，保留原修改时间；勾选同步修改日期时，成对提交目标创建时间和修改时间。始终保留原文件名、图片/视频内容及内嵌元数据，按所选模式核验修改日期保持原样或达到目标日期。随后核对实际时间，文件系统无法保留日期时尝试恢复原日期并报告失败；FAT/exFAT 按最多 2 秒精度比较。扫描使用异步 utility 任务，视频元数据加载不阻塞 MainActor；修复仍在后台执行。取消令牌在文件边界和写入前检查，元数据读取也检查取消；UI 进度最多约 10 Hz。停止或退出不撤回已修复的日期，重新扫描后日期一致的文件跳过。结果和最多 50 条问题详情仅保留于本次应用运行，不安装后台服务、不保存管理员密码。

### 重复图片整理

“本地工具”提供日期修复、重复图片整理、年月归档和拍摄时间重命名四个入口，AppModel 持有独立的 DuplicatePhotosController 及所选工具，切页保留计划/进度；任何本地工具运行时可以返回工具首页并重新进入当前工具，其他工具入口禁用；退出确认计入正在执行的查重/清理。四个工具共用 LocalImageFiles 的根描述符、openat/O_NOFOLLOW、资料库/应用包和路径深度规则，均不发起手机请求或提权。

扫描先按长度分组，只对同长度候选以 1 MiB 缓冲流式计算完整 SHA-256，哈希前后核对文件身份、长度和修改/状态改变时间，读取中逐块检查取消。文件名和文件系统日期不参与重复判定，照片压缩或 EXIF 字节不同则不会分到同组。默认包含子文件夹，最多检查 1,000,000 张；跳过隐藏文件、链接/替身/硬链接、空文件、资料库/应用包及子挂载卷。重复大小为副本逻辑长度之和，不保证实际可回收空间（APFS 克隆、废纸篓未清空等会影响）。

结果按组展示缩略图、完整路径、大小和日期参考。扫描后不勾选任何组；每组默认保留路径较浅、按路径排序的首项，用户可展开逐份选择，或指定扫描范围内的优先保留文件夹；不按日期推断原件。所有选择必须指向本计划中的组和成员，每组始终保留一份。开始清理前显示副本数量并再次确认，批量规则本身不会移动文件。

清理重新计算本组保留项和每份副本的完整哈希，移动前再次检查原根身份、当前路径、描述符身份及保留项仍存在。仅在 NSFileCoordinator 的 forDeleting 协调范围内调用 FileManager.trashItem，保留原文件名及系统废纸篓恢复信息，不使用中转改名、不进行永久删除或硬链接合并。系统废纸篓不可用或文件/根/保留项变化时报告并保留未处理项，不回退到 removeItem；已移入废纸篓的项可由用户在 Finder 找回。停止/退出只停止后续副本，不自动撤回已完成移动。处理后禁止复用旧选择，需重新扫描。

扫描、哈希和清理均在 utility 后台任务中，进度约 10 Hz，结果及最多 50 条问题明细仅保留在当前运行。缩略图仅在可见分组读取，通过根描述符重新验证并打开，ImageIO 最长边 144 像素、最多读取 64 MiB；生成独立像素副本后关闭源句柄。缓存按内容哈希共用，最多 80 项/16 MiB，离开视图取消未完成缩略图读取。测试注入移到临时目录的动作替代系统废纸篓，不触碰用户废纸篓或真实图片。

### 本地图片/视频年月归档

“本地工具 → 图片/视频年月归档”通过独立 LocalMediaArchiveController 管理本机扫描和移动，不发送手机请求。图片、视频和包含子文件夹默认开启，切换选项清除计划，必须重新扫描；进入后只读预览，明确确认“归档已选 N 个文件”才移动。工具间忙碌互斥、切页保留任务、退出计入本地任务并取消剩余工作；不持久化旧扫描计划。

图片优先 EXIF DateTimeOriginal，复用日期修复的有界只读 ImageIO 元数据读取；视频通过 AVFoundation 读取拍摄/容器创建元数据，不解码、不转码。元数据缺失或无效后先复用文件名日期识别（允许仅日期），再使用文件系统创建日期，仍无有效日期则放入“日期未知”。不使用修改日期，下载归档的回退规则保持原样。显式字符串时区保留记录的年月；无时区、文件名和创建日期使用扫描时的 Mac 本地时区。视频排除 1904 等早于 1970 的占位元数据。AVFoundation 支持的元数据随系统和容器格式而异，不等同于 Go 下载归档的有界 atom 解析器。

所选文件夹名称为四位年份（如 2022）时识别为年份目录：只扫描根层散落文件，忽略“包含子文件夹”，已有月份及其他子目录完全不遍历。目标直接为 MM月，不再添加年份层；识别日期的年份与目录年份不一致时保留原位，统计数量并展示最多 50 条原因，绝不移出所选根目录。界面展示识别结果并禁用子目录开关。其他名称的文件夹仍按通用规则递归扫描。

输出在所选根目录内，默认 YYYY/MM月；同月已有 MM月、M月、MM、M 的真目录时复用，多个候选必须先选择。路径预览按每页 20 条分页，全部计划条目均可查看，显示总数、当前条目范围及页码；顶部和底部提供上一页/下一页，翻页后回到预览顶部。每条保留来源、原路径和目标路径，编号在执行时确定。翻页只切片读取内存计划，不重新扫描或移动文件；执行范围由跨页选择集合决定，不受当前页限制；页码由控制器保留，重扫、换文件夹或修改扫描选项时回到第一页，选择月份目标目录则保留页码并更新该页目标路径。源路径已经等于选定目标路径的文件保留原位。同名时复用 DownloadConflict / DownloadConflictDecision 及备份的 DownloadConflictView，展示完整目标路径、待归档源路径、两份文件的大小和修改日期；提供保留两者、跳过、替换、停止归档以及“应用到本次归档的所有同名文件”。保留两者为默认按钮，独占生成 name (1).ext 等编号；跳过保留两边原位且不复制；仅普通单链接目标可替换，目录、链接和其他特殊项禁用替换。保留原空目录。

预览逐项提供复选框，默认勾选所有待归档项；已在确定目标路径中的文件不勾选且禁选，并标明无需处理。支持本页全选/取消、全部选择/清空，翻页或返回工具首页保留选择；修改扫描选项、换文件夹或重扫清除旧选择并按新计划恢复默认勾选。月份目录变化会剔除变为原位的文件，保留仍待移动项的手动取消选择，并默认勾选新变为待移动的项目。未选月份的歧义目录不阻止选中文件执行。

“归档已选 N 个文件”及确认框使用已选数量；执行前固定 ID 集合和月份选择，执行中禁止改选。LocalMediaArchive.apply 验证选中 ID 均属于原扫描计划，再过滤条目，仅检查所选月份是否完成目录选择；空集合不写入文件系统，非法 ID 拒绝整个操作。仅对选中文件打开路径、创建所需目录、询问同名冲突及应用批量策略，进度分母只含选中项。未选项目不会因批量替换或当前预览页而被移动、覆盖或另建目录。

扫描跳过隐藏文件、符号链接/替身/硬链接、资料库和应用包及子挂载卷，最多 128 层和 1,000,000 个媒体文件。计划保存根设备/文件标识，以及文件设备/文件标识、长度、创建/修改/状态改变时间；移动前在 NSFileCoordinator 的 forMoving 协调范围内重新核验根、源路径与已打开文件，并从根逐级以 openat/O_NOFOLLOW 打开父目录。保留两者和无冲突时使用同卷 renameatx_np(RENAME_EXCL) 独占移动，不覆盖竞争出现的同名项；卷返回 ENOTSUP/ENOSYS/EINVAL 等能力不支持时，先尝试已确认的占位校验快速移动；只有普通重命名也不支持时才转入仅新建的兼容复制。仅明确选择替换或本次应用该策略后，在 forReplacing 协调范围内复核目标设备/文件标识、长度、创建/修改/状态改变时间和普通单链接类型，再以同卷 renameat 原子替换，不先删除/截断旧文件、不复制源内容；目标变化重新生成问题 ID 并强制询问，不自动沿用已缓存的替换策略。待处理目录身份变化则拒绝并要求重扫。移动后核对长度、创建和修改日期；归档不会主动改写内容、EXIF 或文件日期，目录日期会因新增/移走文件变化。

快速路径仅由本地归档与重命名工具在已有 NSFileCoordinator 协调范围内显式启用（allowReservedRename），下载引擎保持原提交策略。通过目标目录描述符 O_EXCL/O_NOFOLLOW 创建本次空占位，再重新核验源及根/父目录路径、占位路径和打开描述符的身份、类型、链接数、大小和日期；仅确认仍为本次未变化的空占位后才 renameat 移动原文件。全程不读取或复制媒体内容，不需要单文件副本预留，也不重写创建/修改日期。已有文件/目录/链接不能被占位，变化的占位保留并触发同名重试；取消、路径变化或移动失败只清理仍未变化的本次空占位，不清理其他进程新建或写入的目标。权限等普通错误直接报告；只有普通 rename 也返回能力不支持且占位已清理后才兼容复制。

快速路径提供系统协调及占位核验的保护，不等同于内核 RENAME_EXCL 原子语义。与 Finder/Ferry 等参与协调的操作互斥，并通过 O_EXCL 防止多个快速归档抢占同一名称；不参与协调的软件仍可能在最终检查和重命名之间修改目标，因此使用时避免其他程序同时写入目标目录。强退/拔盘可能留下空占位；后续仍按正常同名规则询问，不自动覆盖或清理历史占位。支持 RENAME_EXCL 的卷继续使用原内核防覆盖路径。

ArchiveFileMove 的兼容路径使用目标目录描述符加 O_EXCL/O_NOFOLLOW 创建新文件，先检查单文件副本空间和 64 MiB 预留，复制中继续检查空间与取消。以 1 MiB 缓冲读取源并计算 SHA-256，复制结束设置原创建/修改日期并 fsync，再独立读取副本和源文件核对完整摘要及长度；APFS 时间按原精度比较，FAT/exFAT 按最多 2 秒文件系统精度比较。删除源前再验证根、源路径/描述符、目标目录身份和副本路径；只有全部成功且未取消才 unlinkat 源文件。源删除失败、校验失败或正常取消时清理本次创建的副本，若目标名称已指向其他文件则不删除该项；清理失败会明确报告残留路径。兼容路径不保留原文件标识，文件内容与 EXIF 保持，日期以卷精度保留；不复制或修改未选文件。进度增加当前本地复制/校验阶段，整体文件数仍仅计已选项。

仅在直接移动不可用而实际进入兼容复制时，需要额外一次本地复制及源/副本读取校验，耗时随文件大小和盘速变化，当前目标名称在复制期间可能暂时不完整；正常失败或取消保留源文件并清理副本，强退或拔盘可能留下一份副本，重新操作需先检查目标。明确选择替换仍使用已批准的原子重命名分支。

后台执行并以约 10 Hz 发布进度，文件边界和移动前检查取消。遇同名后 utility 工作线程通过独立 NSCondition 桥接器等待，MainActor 发布问题，UI 通过问题 ID 只接受当前回答，不反复执行文件操作。任务取消、控制器销毁或退出时唤醒等待并丢弃迟到回答；仅本次 apply 保存全局同名策略，下一次重扫执行时重新询问。返回工具首页不丢失问题，卡片显示“等待处理同名文件”，再次进入继续选择。停止保留已完成的移动/替换，剩余项留在原处。结果区分已归档、其中替换、跳过、原位及失败数量，展示最多 100 条实际移动路径（替换另作标记）及 50 条问题明细，结束后需重新扫描。仅用临时合成图片及演示视频的副本验证，不擅自整理用户硬盘照片。

### 按拍摄时间重命名

“本地工具 → 按拍摄时间重命名”是独立入口和独立控制器实例，使用 LocalMediaArchiveController(operation: .renameMedia)，与年月归档共用经过验证的扫描、选择/分页、取消及同名执行流程；AppModel 持有 mediaRename，切页保留状态，忙碌互斥及退出计数包含此工具。请求不经过 USB/MTP，也不访问真实手机。

图片/视频和包含子目录默认开启。图片优先 EXIF DateTimeOriginal/OffsetTimeOriginal/SubsecTimeOriginal，其次 EXIF 数字化创建时间和 PNG 内嵌创建时间；对 ImageIO 未返回的 PNG tEXt 创建时间，额外读取有界元数据（最多 4096 个块、单个文本块最多 4096 字节），跳过像素块并核对 CRC，支持 ISO / EXIF 格式及 RFC 1123 日期。ImageIO 复用只读描述符、8 MiB 上限且不解码像素的元数据读取。视频通过 AVFoundation 读取拍摄/创建元数据，排除 1904 等占位时间，不解码或转码。缺少有效元数据时间时，默认复用 PhotoDateRepair.dateFromFilename（allowDateOnly: false）识别文件名中的完整年月日时分秒，来源标为 filename；仅日期、非法日期、非法时间或多个冲突日期/时间跳过，元数据和文件名均不可用时计入 noDate。不使用文件创建或修改日期，不采用 TIFF 通用 DateTime。文件名时间按扫描时的 Mac 当前时区解释，并用于命名和同步两种文件日期。共享 MediaCaptureTimestamp 严格验证日期、时区和小数秒；文件名保留字符串记录的当地年月日时分秒，文件日期使用解析后的绝对时刻。无时区或只有绝对日期的值使用扫描时的 Mac 时区生成日历字段。

图片名为 IMG_yyyyMMdd_HHmmss 加原扩展名，视频名为 VID_yyyyMMdd_HHmmss 加原扩展名；扩展名大小写、内容和 EXIF 保持，文件在原父目录内重命名，不建立年月目录、不转换格式。只处理勾选项，预览显示旧/新路径及创建、修改日期变化。已符合名称与日期的条目禁选；已有“ (1)”等保留两者编号在重复扫描时稳定，已命名但日期不符的文件只同步日期。仅大小写变化可识别为同一原文件并直接改名，不询问自我替换。

同名时沿用备份弹窗，支持保留两者、跳过、明确替换及本次全部应用。目标本身若是其他待改名源文件则禁止替换，避免批量重命名顺序造成源数据丢失；明确替换已命名目标后，若该目标也有本次日期同步计划则跳过已被替换的旧项。跳过/未选文件不主动改名或写日期；同名目标仅在明确替换授权后覆盖。

成功改名后，在协调范围内捕获目标文件身份，重新打开目标并验证其未变化，再通过成对 fsetattrlist 同步创建和修改日期；DateTimeOriginal 的小数秒按卷精度保留。名称已符合时验证原文件后直接同步日期。同步失败会尝试恢复日期，并明确记录“已重命名但日期同步失败”，实际改名不伪装成未发生；结果分别统计已重命名、已同步日期、跳过和失败，展示最多 100 条实际处理路径与 50 条问题。结束后须重扫，停止不撤回已完成改名或日期调整。

扫描跳过隐藏文件、链接/替身/硬链接、资料库、应用包和子挂载卷；年份目录在此模式下只是普通目录，不触发归档的仅根层逻辑。目录枚举由工具统一处理包跳过，不对普通链接叶节点调用 skipDescendants，避免错误跳过后续正常子目录。

### 列表选择与排序

列表用原生 Table 的 selection 与 primaryAction 处理单击、多选和双击，名称单元格不安装拦截选择的手势。勾选框、全选和右键下载共用同一组对象 ID。

名称、大小、类型、修改日期列分别绑定值 key path 和 AppModel 的 sortOrder，使用 KeyPathComparator 保存字段与升降序。DirectoryOrdering 始终先区分文件夹，再应用列比较器；名称和类型采用本地自然比较，大小和日期按原始数值，最后按自然名称与对象 ID 消除同值的不稳定顺序。文件夹不展示大小，大小排序统一将其视为 0。列排序只处理已读取的数据，列表与网格共用结果及选择对象 ID。

表头切换的排序任务在后台执行，合并连续点击并支持取消，设备清空、目录导航、新设备操作及退出时取消旧排序；发布结果前校验排序代次，避免旧结果覆盖新目录或较新的排序。排序期间不阻塞主界面，不额外打开 USB。

首次按大小排序且大小未知时，允许通过串行会话补齐大小后排序；失败须恢复原排序，不能自动循环重试。已有大小时只在本地重排，不重新读取手机。

### 预览与缩略图

目录栏支持列表与 LazyVGrid 缩略图视图，视图偏好保存在 UserDefaults；两者共用对象 ID 选择、过滤和下载。空格键通过仅作用于浏览窗口的 AppKit 本地事件监听处理，不拦截搜索框等文本编辑器的空格。图片、PDF、RTF 与 Office/OpenDocument 使用系统 QLPreviewView，关闭时调用 close；音频与视频使用 AVPlayerView，提供播放、暂停和拖动，视频额外提供全屏，关闭时暂停并释放 AVPlayerItem，不支持的编码显示本地化提示。

纯文本与 Markdown、CSV/TSV、日志、JSON、XML、YAML 由 FileTextPreview 在后台读取本地暂存文件的前 1 MiB，支持 UTF-8、带 BOM 的 UTF-16/32 及常见旧编码，截断时提示下载全文。NSScrollView/NSTextView 只读显示并允许复制，Markdown 不进行 HTML 渲染。完整文件仍由 helper 按已有校验流程读取；文本显示上限不改变传输范围。

RemoteEntry.isPreviewable 对齐 helper 的 PreviewKind，包含图片、视频、音频及支持的文档；isThumbnailEligible 和 MediaKind 仅包含图片/视频，几何需求与缩略图队列使用后者，不能因扩展空格预览就自动下载文档或音频。选择未知格式也可打开说明界面，但客户端不发起读取；helper 同样拒绝未列入预览白名单的格式，目录不支持预览。

MediaController 与 AppModel 共用同一个 EngineRunner。网格通过单元格与滚动视口的实际交集统一更新缩略图需求，包含少量临近区域；离屏时撤销尚未开始的需求，每批最多 24 项，不依赖 LazyVGrid 的预创建单元格作为可见范围。后台读取不禁用浏览界面，前台导航/下载先使媒体回调失效，向 helper 发送取消信号，持续消费事件直到 helper 退出再启动下一操作；不能直接取消 Swift 读取任务后就假定 USB 已释放。图片通过 ImageIO 在后台缩放为最长边 384 像素；可见项由独立强引用保留，离屏缓存使用 NSCache，限 128 项、约 48 MiB，缓存淘汰不会记录为文件读取失败，再次进入视口时可补载。临时源文件在处理后删除。刷新、切换存储、断开或切换模式清空媒体缓存。

设备未提供缩略图、路径无效或解码失败按项目记录原因并提供手动重试，不阻塞同批的其他结果。读取请求失败后，先消费完事件等待 helper 结束，再间隔一秒用新请求自动重试一次；仍失败则在网格显示错误与“重试”按钮，避免无提示停队列或无限重连。错误事件本身不视为 helper 已退出。仅成功接收完整批次才视为批次完成。

### 筛选与日期

隐藏文件显示偏好使用 UserDefaults 保存，默认 false。完整目录保留在 `entries`，可见列表仅在目录、搜索词或偏好变化时重新计算并缓存；隐藏或过滤掉的选择会被移除。下载请求携带当前 `showHiddenFiles`，Go 在生成下载计划时递归应用：false 时跳过点号文件和目录，不遍历隐藏目录；true 时包含隐藏项目。搜索只影响当前列表的选择。

DirectoryFilterInput 捕获不可变的目录与筛选条件，单次遍历生成可见数组、对象 ID 集合、隐藏数量和年份选项。年份、月份和类型菜单回调不得同步遍历大目录，仅更新条件并排队，通过主 RunLoop 的 default 模式等待菜单结束跟踪后提交，不使用固定等待；普通大目录搜索合并 60 ms 内的连续输入。年份统计在目录内容、类型与隐藏条件不变时复用，最近 8 组完整筛选结果保存在内存中，目录内容或顺序改变时清空结果缓存。再次切回已缓存条件无需遍历，重复条件不重新发布可见数组。大于 1,000 项目录的其他可见列表刷新也走后台，小目录普通刷新保持同步。筛选代次在新条件、导航、断开和退出时失效，旧计算不得覆盖新目录或新条件。年份选项和数量相同时不重复发布，避免原生菜单重建。

筛选期间展示“正在筛选”，文件选择、全选、预览、上下文下载与菜单快捷下载共同禁用，selectedEntries 不提供旧数据；完成后再按新可见 ID 集合保留匹配选择并恢复媒体加载。几何缩略图需求还需通过当前可见 ID 集合校验，不能使用筛选过渡期间的旧单元格。全选复用后台生成的 ID 集合，不在主线程重新遍历目录。

目录读取后，在后台排序时一并建立 DirectoryYearIndex，使用公历与系统时区将正值修改时间映射为年份；索引与目录快照一起缓存，排序和年份切换不重复解析日期。年份选项按隐藏设置及当前媒体类型统计当前目录中的文件，不受搜索词影响，从新到旧排列，并提供“日期未知”。可见列表同时应用年份、媒体类型、搜索与隐藏条件，选择与它取交集；下载仍发送具体对象 ID，无需修改引擎协议。

批量属性与逐对象 ObjectInfo 共用 vendored MTP 的 ParseDateTime：无时区的手机日期按 Mac 本地时区解释，假定手机与 Mac 时区相同；明确带 Z 或数值时差的日期保留其时区语义，再转换为 Unix 秒。支持小数秒与设备附加的末尾句点，缺失日期保持未知、非法日期报错。不得先将无时区日期当 UTC 再转换为本地时间，否则晚间文件会跨日、跨月甚至跨年。列表显示、年月筛选及下载文件修改时间均使用同一解析结果，不从文件名或 EXIF 推断日期。手机与 Mac 时区不同时，无时区数据无法恢复手机的实际时区。

具体年份与“日期未知”只匹配文件，排除目录，避免整目录递归下载混入未筛选的年份。切换年份使旧媒体需求失效，缩略图几何偏好包含年份上下文，不能从旧筛选结果请求媒体。刷新当前目录保留年份条件，零结果仍保留该选项；目录导航、存储切换及断开连接恢复全部年份。首次 USB 目录读取范围不受年份筛选影响。

月份同样使用当前目录文件的修改日期与本地时区，可跨年选择，也可与年份组合。具体月份排除目录及日期未知的文件；月份数量按当前年份、媒体类型与隐藏条件统计，并按年份缓存。月份必须进入筛选结果缓存键与缩略图需求标识。刷新不得放宽月份条件，跨目录或换设备恢复全部月份。年月切换不得加入固定等待，菜单结束跟踪后提交；统计和近期筛选结果在条件不变时复用，目录内容、类型或隐藏条件变化时正确失效。

DirectoryMediaFilter 提供全部类型、图片、视频。图片和视频按统一的大小写不敏感扩展名表识别，覆盖常见位图、矢量图、相机 RAW 及视频容器/码流；RemoteEntry 和 transfer.MediaKind 的扩展名集合必须保持一致，避免列表识别为媒体后被 helper 拒绝。媒体筛选排除文件夹，切换时清除不再可见的选择并使旧缩略图需求失效，几何偏好包含类型上下文。刷新保留类型，跨目录导航或换设备重置为全部类型；清除筛选同时重置年份、类型与搜索，不修改隐藏文件偏好。预览/播放能力仍取决于系统解码器，普通下载不受编码支持限制。

### 导航与目录缓存

AppModel 在内存中保留当前存储浏览路径上的目录快照及对应排序条件。返回上级时，条件相同则直接恢复；条件不同则复用快照数据在后台本地重排，均不调用 helper。路径之外额外保留最近 4 个目录、最多 100,000 项，按 LRU 淘汰。导航清空搜索与选择，并按当前隐藏设置重新计算可见列表。只有成功完成且未取消的目录请求会写入缓存；手动刷新先使当前快照失效、清除路径之外的最近缓存并重新读取。切换存储、断开、重新连接和切换演示模式时清空缓存。后台排序结束后再次检查设备代次，避免旧设备结果恢复列表。

缓存恢复需提示缓存状态；失败或取消的读取不能因后续本地重排而变成有效快照。

BreadcrumbPath 将存储根目录和 folders 的各级路径渲染为按钮；空间不足时用菜单提供完整祖先列表。跳转通过路径深度定位，截断 folders 后复用 loadDirectory(useCache: true)，不按名称重新查找，也不逐层发送读取请求；返回上级使用同一个入口。只允许当前路径的祖先，忙碌状态及当前目录点击不触发导航，搜索、选择和年份条件按正常跨目录规则重置，排序保持。

### 经常访问

只对成功目录导航计次，根目录、手动刷新、失败与取消均不计。按访问次数和最近访问排序，记录按已验证手机与存储隔离，仅持久化名称路径，不持久化 MTP 对象 ID。无可靠 USB 序列号时只保留本次连接记录，隐藏路径遵循隐藏设置。

重连后的入口逐级解析精确 UTF-8 名称，完整成功后才提交页面、缓存与统计。缓存未命中时不得提前切换目录；共用前台预留和完整文件边界调度，换机或取消时丢弃旧结果。用户操作与本地历史清理见 [usage.md](usage.md#经常访问)。

### 本地化与外观

设置窗口包含通用、文件显示、下载、USB 连接和体验与测试分区。通用设置提供跟随系统/简体中文/英文及跟随系统/浅色/深色；语言下次启动生效，外观即时应用。翻译位于 Swift 的 lproj 资源、Go 的嵌入式 JSON 以及系统 InfoPlist.strings，不在界面里按语言编写成对文案；资源与新增语言步骤见 [localization.md](localization.md)。EngineRunner 通过 FERRY_LANGUAGE 环境变量与 helper 对齐语言，不改变 JSON 协议或原始文件名。主窗口、设置与系统控件通过 NSApp.appearance 继承同一外观偏好，不再使用 SwiftUI preferredColorScheme 叠加窗口覆盖；跟随系统时清空应用外观，默认不覆盖系统。

主窗口使用原生标题栏，不为静态工作模式文字创建工具栏控件，避免系统工具栏背景呈现为输入框。演示模式用主标题旁的橙色图文徽标明确标注，与标题按文字基线对齐；标题行设置最小高度，切换模式不改变标题栏结构。连接、读取和下载状态继续显示在主标题下方。

### 下载页面与后台调度

DownloadDestination 使用 UserDefaults 的 downloadDestinationPath 保存用户确认选择的绝对本地目录路径，不设开关。首次或非法偏好使用系统下载目录；合法但不存在/未挂载的路径仍恢复原选择，启动时不扫描文件或改写记录。AppModel.setDestination 是选择更新入口，仅接受有效 file URL；选择面板取消不调用该入口。下载入队前检查目录存在、类型为目录且可写，不可用时显示连接硬盘或重新选择的错误，拒绝入队和引擎请求，不创建目录、不回退。检查仅为当前可用性提示，入队后引擎仍执行自身的路径、空间和提交校验，处理排队期间拔盘或权限变化；已有任务的目标快照不随新选择改变。仅保存路径，不自动追踪目录重命名、移动或不同挂载路径。

下载任务使用独立页面，侧栏入口统计未结束任务，浏览页只保留一行状态。切页不得影响队列执行或重读目录，须保留浏览路径、筛选、选择和列表状态；隐藏的浏览页不得响应选择、下载或预览操作。

任务列表按添加顺序倒序展示，最新任务在最上面；完成、失败、取消或继续不改变任务位置。仅 DownloadQueuePresentation 反转展示顺序，后台任务数组与执行调度保持原顺序。浏览页摘要优先显示活动任务，无活动任务时显示最新添加的任务。

任务卡片标题下显示入队时的筛选摘要，包含类型、修改年份、修改月份、非空搜索词及隐藏文件设置；未限制的维度明确显示全部类型/年份/月份，日期缺失显示日期未知。摘要在 AppModel.download 入队时生成并随 DownloadTask 保留，后续浏览筛选、进度、取消或继续不重新计算；不将这些展示信息加入 helper 协议，不改变冻结的对象 ID 或递归下载规则。文案来自中英文资源，最多显示两行，悬停查看完整摘要。

下载展示按变化频率分层。DownloadQueueController 保留原始任务快照供状态查询，但界面不订阅整份 tasks：DownloadQueuePresentation 仅在任务增删、队列按钮状态、待完成数量或焦点任务变化时通知列表/状态栏；稳定的 DownloadTaskRowModel 仅通知自身可见字段发生变化的行，已结束任务不随其他任务进度更新。任务行保持同一个 TimelineView 和原生进度视图：运行/取消中使用每秒周期计划，其余状态使用单次显式计划，不安排未来时刻；完成时不替换整个视图，历史任务没有周期计时器。DownloadConflictState 仅在冲突 ID/任务 ID 变化或清空时发布，主窗口的弹窗呈现不观察字节进度。按钮与决策仍转交原控制器/后台驱动，避免 UI 展示模型取得 USB 调度所有权。

任务列表采用 16 pt 间距、独立圆角边框与 20 pt 内容内边距，正在运行的卡片边框强调状态。标题与状态徽标位于顶部，进度轨道、四列统计和底部文件/操作栏共享内容边缘；四列固定为文件数量、传输量、已用时长及平均速度（运行中为预计剩余），各列标签和值左对齐。小舟绘图保留原有两端 14 pt 安全区，任务行仅通过水平布局补偿让轨道与文字对齐，不改变字节进度坐标或动画。文件名中间截断并提供完整路径提示，按钮保持单独的底部操作栏。边框与背景适配系统浅深色，不引入模糊阴影、额外进度订阅或定时器。

已完成、已取消和失败任务在有有效字节数与正有限用时时显示平均速度：(transferred - reusedBytes) / TransferTiming.elapsed。总用时使用单调时钟，含开始后的准备、前台交接、冲突等待和收尾，不含尚未开始时的队列等待；结束时冻结。零传输、未开始或无有效用时不显示。提前跳过及恢复复用的逻辑进度计入 reusedBytes，不计实际传输速度；已读取但跳过的文件仍计入实际传输量，exFAT 本地提交复制不重复累计；该指标是任务整体平均传输速度，不是目标盘净写入速度。计算复用任务行现有快照，不新增计时器、进度发布或 USB 请求。

任务卡片的 SailingProgressView 复用 sailboat.fill，水面轨道和短波纹为静态图层，小舟的位置使用真实字节进度；未知总量时留在起点，不制造百分比。SailingProgressNSView 仅用 Core Animation 对小舟执行三秒周期、约 ±1.2 pt / ±2° 的上下浮动和摇摆；横向进度插值不增加原有最多 4 Hz 的发布频率。动画不使用 SwiftUI 帧定时器、不通知任务模型，也不驱动文件循环。航行中的循环动画仅在 running 且应用激活、窗口可见且未最小化/完全遮挡、进度条与滚动视口相交、未启用减少动态效果时播放；切页拆除、移出窗口、滚出视口、等待选择、取消和终结均移除循环动画。原生通知只监听应用、所属窗口和祖先 clip view。completed 的码头与小旗整体可见右缘精确对齐进度条右端点，包含横梁描边，不再让图形向右伸出；仅显示码头和小旗，小舟及短波纹不保留在最终场景；cancelled 在原进度位置保留小舟并显示灰色船锚；failed 在原进度位置以橙色感叹号浮标替代小舟；waiting 仍显示静止小舟。场景使用本地矢量图层，沿用 34 pt 高度与原进度坐标，不改变卡片位置、字节进度或状态文案。只有已显示航行场景实时变为完成且满足相同可见性/减少动态效果条件时，播放一次最长 1.1 秒的交接动画：小舟从当前显示位置到达终点并淡出，码头延后渐入、小旗升起，淡出与渐入短暂重叠以保持连续，最终只保留静态码头和小旗。初次显示历史任务、切页或滚动回来不补播；进入后台、隐藏、移出视口、减少动态效果、场景变化和拆除时直接移除动画并显示最终状态。继续取消任务时清除船锚/浮标/码头，恢复航行场景。浏览页底部的小进度条维持原样。

浏览页拆为 BrowserPageView，在 RetainedBrowserHost 的独立 NSHostingView 中保持一次挂载。切换下载页时隐藏原生容器并冻结其 hosting frame，下载行布局不会重新调整隐藏 Table/LazyVGrid；返回时恢复当前尺寸，不重建原生表格。目录、排序、选择及原生滚动状态继续保留。隐藏浏览页不挂载高频下载状态内容，使用等高占位保留 viewport；locale 与 tint 显式注入，外观继续继承 NSApp.appearance。相同的原生 selection/sort 回调不重复写入 AppModel。

逐文件调度在独立后台驱动执行，不等待 MainActor 或 UI 快照发布；前台预留、请求认领、取消与引擎 epoch 捕获须原子协调，只在当前完整文件结束后交还会话。取消下载只更新 cancelling 状态，不中断正在进行的 helper 请求；消费到完整请求及 ready 后再发送 cancel，保留健康会话。当前请求返回冲突时取消优先，不弹出新的选择窗口；最后一个文件已完成则按完成处理。真实传输错误即使发生在 cancelling 期间也须暂停后续队列，不自动循环重连。字节进度最多 4 Hz，仅任务摘要变化可使 AppModel 发布，禁止每次进度导致整窗布局；generation、revision 和定时器代次须屏蔽旧事件。

队列冻结入队时的手机、存储、对象、目标目录、直接保存/新建文件夹方式、照片创建日期、按拍摄年月归档选项和隐藏设置。保持单个活动任务，完整文件之间让出，不保留跨请求的半文件；独立取消、故障暂停、原设备手动继续和前台读取失败后的清理契约见 [usb-access.md](usb-access.md#串行会话与释放)。

任务恢复支持同一 helper 内的内存检查点，以及退出/重启/重新连接后的持久化恢复。DownloadTaskStore 在应用数据目录的 `Ferry/download-tasks.json` 保存未完成任务的原请求、标题、筛选摘要、报告/恢复路径和生命周期快照；文件权限 0600，临时文件同步后原子替换，最多 128 条、64 MiB。仅任务加入、开始、取得恢复路径、结束、连接失效和移除等生命周期变化写入索引，字节进度及逐文件交接不重写该文件。写入失败须显示原因并拒绝启动尚未记录的新任务；损坏索引不覆盖、不据此发起传输。完成任务从持久化索引移除，完成历史仍只保留在当前应用运行中。

启动时未完成任务显示“等待恢复”，不自动连接或传输。该状态不占用调度会话，允许用户连接原手机；连接后点击“继续未完成”，界面按原恢复标识及设备指纹、存储名称与容量唯一匹配当前手机和存储，更新当前 USB 路由及存储 ID；实际文件 ID 由 helper 重新定位。原保存位置不可写时保留记录供重试。恢复沿用同一任务 ID、冻结选项和原输出根，不新建批次目录；未开始任务按原目录和所选名称/元数据重新定位后正常规划。旧 helper 的 sessionIdentifier 与 resumeToken 不持久化，原会话仍可用时继续走 resume/restart；跨会话走 recover。EngineRunner 禁止这三种操作在没有已连接 helper 时启动进程或触发授权。

“清理已结束”保留可继续的任务；卡片的“移除任务”只删除任务索引项，不删除已下载文件或报告，也不再自动显示该任务的恢复入口。断线、引擎错误和退出仍按原顺序清理会话，持久化记录保持；恢复失败不会自动重试或触发其他任务重新连接。恢复时清空计数并重新计时，平均速度和 ETA 排除已核验复用及提前跳过的逻辑字节，不增加高频根视图订阅。

### 退出确认

菜单、⌘Q、Dock 正常退出和关闭主窗口须先确认，默认取消。取消不得关闭原窗口或触发 shutdown，未结束任务提示使用后台队列实时计数。确认后才执行清理，窗口关闭不得再次重复提示；须保留 SwiftUI 原窗口代理的其他行为。

## 进程边界

`Sources/FerryCore` 定义请求和事件、字节流分帧及进程管理。界面不加载 Go 动态库，不传递文件内容；文件字节直接由引擎写入目标卷。界面通过参数和标准输入直接启动 helper；一次性管理员授权由 relay 调用系统 AppleScript 启动提权 helper，命令参数分别经过 shell 与 AppleScript 转义。

## 进程协议

默认 CLI 模式接收一个 JSON 请求，执行后退出；应用使用 `--serve` 模式，复用同一个设备与 MTP 会话，串行接收多行请求。支持 `connect`、`list`、`sizes`、`download`、`preview`、`thumbnails`。标准输出每行一个 JSON 事件；标准错误用于原生库诊断。终结事件为 `connected`、`listed`、`sized`、`yielded`、`completed` 或 `error`。`--serve` 模式下成功终结事件之后发送 `ready`，EngineRunner 消费到该标记后才允许下一请求；失败返回 error 并退出，调用方必须消费到 EOF 并等候进程清理。系统接管未获授权用 `error.state: authorization_denied`，停止本次接入的自动重试。

示例：

```json
{"operation":"list","deviceKey":"连接响应中的设备摘要","storageID":1,"parentID":0,"objectIDs":[],"destination":""}
```

`parentID: 0` 表示根目录。设备对象通过 MTP handle 定位，避免逐路径扫描。连接响应返回厂商/型号/序列号摘要，每次操作验证，减少换机后的过期句柄风险。设备重新连接导致 handle 变化时仍需刷新；没有序列号的同型号设备身份保证有限。

`diagnostic` 是非终结事件，仅记录日志，不改变 `ready` 或请求终结状态。修改请求或事件时，同步更新 Swift 的 `Sources/FerryCore/Models.swift`、Go 的 `engine/internal/transfer/types.go` 及两端协议测试。

应用快速浏览默认请求 `includeSizes=false`，仅受支持的非根目录省略大小；CLI 省略该字段时仍读取完整元数据。`size=-1` 表示未读取，不得显示为 0 B。`sizes` / `sized` 按对象 ID 完整合并，保留筛选、选择及目录快照；缺失、重复或负值必须整体拒绝，不能部分发布。下载递归 List 与 Info 必须保持完整大小，未知值不得进入空间预检或文件写入。

`download` 请求的 `showHiddenFiles` 默认为 false，省略时同样跳过隐藏项目。文件数、字节数、空间预检和传输报告均以过滤后的下载计划为准。应用明确发送 `downloadLayout: direct`（默认直接保存）或 `folder`（另建任务目录），并发送 `reportDirectory` 指定应用数据目录；引擎在其下创建独立报告目录。省略 `downloadLayout` 的旧 CLI 保留原有任务目录、`files` 与报告布局及同名拒绝行为。状态/进度事件与协作下载终结事件可携带 `reportPath`；它用于任务页报告查看，不改变终结或 ready 语义。报告新增可选 `output` 标明实际输出位置，项目 `path` 记录自动编号后的真实相对路径。

应用的协作下载发送 `promptConflicts: true`。若目标文件存在，或归档中存在多个同月候选目录，helper 返回终结 `yielded / state=waiting` 与 `conflict` 载荷，之后仍发送 ready。载荷包含独立冲突 ID、类型（file / monthDirectory）、显示路径、原文件和新文件的大小/修改日期、canReplace 与候选目录列表。普通文件及恢复中已确定目标路径的文件先检查冲突，再读取手机内容；选择跳过（包括本任务全部应用）不读取内容、不创建该文件的临时文件。首次年月归档仍先完整下载以解析日期；下载期间新出现的同名项目也在提交前询问。这两种等待仅保留一个已完整下载、校验、同步并关闭句柄的临时文件。所有等待均无活动 USB 读取或半文件。后台驱动进入 waiting 状态，不自旋请求 next；允许前台按串行会话规则使用 helper，保持设备/模式切换禁用。

用户回答通过 `downloadAction: resolve` 和 `conflictDecision`（id、choice、applyToAll、directory）发送。文件 choice 为 keepBoth / skip / replace，目录选择为 directory 且必须精确匹配候选项；任务 ID、存储和冲突 ID 同时校验，不能把客户端传入的任意路径用作替换目标。applyToAll 仅在当前 DownloadJob 内保存文件冲突策略，新的任务清空；同月目录选择在任务内按年月缓存。替换前发现已显示目标变化会生成新的冲突 ID 重新询问。停止等待任务使用正常 cancel 请求，不中断空闲 helper；断线、取消、EOF、退出均清理待处理临时文件并清除前端弹窗，过期回答不得启动新请求。

持久化恢复协议为可选扩展。connected 可携带 recoveryIdentity；真实手机使用厂商、型号及可用 MTP 序列号的 SHA-256，缺失时使用已选择 USB 目标的序列号；两种序列号均不可用时不提供跨会话恢复，任务状态消息说明仅支持当前连接。download 请求的 durableRecovery 默认 false，应用开启时同时发送 recoveryIdentity、sourceDirectory（手机当前目录的组件数组）、sourceSelection（入队时的所选 RemoteEntry 元数据）和 sourceStorage（原存储快照）。begin 在读取内容前验证目录与所选对象、建立独立恢复清单，并以 status 和 yielded 的可选 recoveryPath 返回清单路径；手机缺少稳定标识时退回已有内存恢复，不阻止正常下载。

跨会话使用 `downloadAction=recover`，携带原任务 ID、冻结的选项和 recoveryPath，同时使用当前连接的 usbTarget 与 storageID。清单的设备指纹和恢复标识、其余原请求必须匹配；当前存储按原名称及容量唯一确认。尚未开始的任务不带 recoveryPath，按保存的 sourceDirectory/sourceSelection 重新定位所选对象后规划，不能使用旧对象 ID。已有 helper 内的 resume/restart 保持原有请求绑定和令牌语义。上述新增字段在旧客户端请求中省略，不改变 diagnostic、终结与 ready 的处理。

正常 cancel 完成清理后，可在 completed/state=cancelled 中返回可选 resumeToken。downloadAction=resume 必须携带该令牌、原任务 ID 和与 begin 完全匹配的冻结请求；令牌只定位当前 helper 的内存检查点，不接受报告路径或客户端提供的计划。成功恢复消耗令牌，返回 yielded/state=running，后续仍使用 next/resolve/cancel 和 ready；再次取消生成新令牌。restart 只用于本连接中尚未开始便取消的任务，执行原计划的正常准备，不提供跨连接恢复。progress 可携带 Int64 reusedBytes，表示未发生本次手机内容读取的逻辑进度字节，包含恢复核验/复用和传输前跳过，必须从速度和 ETA 的实际新传输量中扣除；省略为 0，新任务/新恢复前清零。bytes 和 totalBytes 保持原计划的逻辑进度，全部跳过仍完成文件数与字节进度。旧客户端可忽略新增字段。

DownloadCheckpoint 在取消前捕获输出根、报告根及日志的文件身份，正常取消仍关闭全部句柄、删除临时文件。内存恢复保留原计划、编号和月份选择，令牌预算仍为 32 个任务、1,000,000 项，helper 退出时释放。

跨会话恢复使用报告目录内独立、带版本的 `恢复记录.json`（最多 128 MiB）保存初始计划、手机完整路径组件、冻结请求、输出/报告/日志的文件身份和提交方式；不从面向用户的传输报告重建计划。后续沿用同步的 `任务记录.ndjson` 追加目录创建、文件运行/完成/明确跳过及冲突的实际目标；recoveryIndex 为计划中的稳定序号，recoveryTarget 保存已确定的输出路径。恢复时校验根目录、日志身份、普通文件类型、任务选项、路径范围、源选择范围和大小边界；通过 os.Root 访问，日志持有排他 flock，拒绝并发恢复。日志最多 512 MiB、单条最多 256 KiB，按行重放，只有末尾未完成的一行可在锁内截去，其余损坏拒绝；复用前不执行覆盖或删除目标文件。

每个 Step 按原手机路径在当前存储中逐级精确定位，名称歧义、缺失、类型变化或文件大小/修改时间变化即停止。目录列表缓存限制为 256 个目录、合计不超过 1,000,000 项；重新取得的 ID 替换旧 ID。已完成文件仍核对本地普通文件长度和 SHA-256，缺失或损坏时重新下载并遵守冲突规则；已完成目录复用原实际路径且拒绝链接；缺失的已保存年月目录按原路径重建，校验/重下前逐级拒绝被链接占用的父目录；明确跳过的项目保持跳过，不要求再次读取手机。继续按文件边界让出，未提交临时文件不复用，未完成文件从头下载。保存的月份目录选择及编号路径保留，文件“全部应用”策略清空。无法识别手机端名称、大小、修改时间完全相同的内容变化，不声称已与手机端摘要比对。

保留两者仍使用独占提交/复制及编号。跳过不写入目标、不修改其创建日期，报告状态 skipped；提前跳过的项目不记录 SHA-256，已读取后跳过的哈希仅属于新读取文件。completed 计入已处理文件数，skipped 另行计数。替换仅允许用户明确同意的本地普通文件，并将已校验、同步的同卷临时文件直接通过 os.Root.Rename 原子替换；提前确认的目标在下载后还须核对文件身份、长度和修改时间，变化则重新询问并复用完整临时文件。不得先删除/截断旧目标，不替换目录或链接。普通源目录依旧编号隔离，不提供整个目录替换。报告 conflictAction 记录 keepBoth / skip / replace。未发送 promptConflicts 的旧客户端保持非交互行为；单请求 CLI 不支持 promptConflicts=true，避免无人处理的等待。

`usePhotoCreationDate`、`archivePhotosByMonth` 和 `archiveVideosByMonth` 为可选布尔请求字段，省略均为 false；Swift 与 Go 同步定义，队列在入队时冻结、DownloadJob 在 begin 时捕获，内存检查点继续保留这些选项。前两个图片选项都关闭时不读取 EXIF。开启任一图片选项时，仅对图片在临时文件完成长度校验、SHA-256 和同步后，以 os.Root 打开的文件描述符交给系统 ImageIO 读取一次 DateTimeOriginal、OffsetTimeOriginal 和 SubsecTimeOriginal，通过 pread 提供数据，不解码像素或拼绝对文件路径。两个图片选项共用解析结果，不重读手机或 EXIF；视频归档不会扩展照片创建日期选项的作用范围。

创建日期选项只在提交成功后，通过 fsetattrlist(ATTR_CMN_CRTIME) 设置本地创建日期，保留图片字节、EXIF、修改时间与远端元数据；日期缺失时不猜测。明确时差优先，无时差使用 Mac 本地时区。可选报告字段 photoCreationTime 记录成功应用的 Unix 秒，creationDateWarning 记录非致命错误。预览不使用这些下载选项，状态/终结/ready 语义不变。

年月归档独立选择图片/视频，目标为输出根目录的 `YYYY/MM月/文件名`。图片优先取 EXIF 拍摄当地年月，缺失/无效时取手机修改日期的 Mac 本地年月，再缺失放入固定“日期未知”目录；目录命名不随界面语言改变。monthArchivePlan 保留未启用归档类型所需的原目录与实际空目录，移除仅承载已归档媒体的源目录。图片与视频共用月份目录选择缓存，兼容 MM月 / M月 / MM / M 的真实年月目录，唯一匹配直接复用，多个匹配由协作界面选择；非交互客户端按上述顺序选择首个匹配。普通文件或符号链接占位不可作为目录复用；通过 os.Root 创建和校验路径，不覆盖或重命名原有项目。最终文件仍使用既有独占提交/复制与编号机制；只有显式设置新归档选项的旧 CLI 才启用新冲突策略，省略选项保持旧行为。报告可选字段 sourcePath、archiveDate、archiveDateSource 和 archiveDateWarning 分别记录原始路径、采用日期、来源（exif/video_metadata/container/modified/unknown）和读取错误；path 为实际保存路径。

video_date.go 仅读取通过 os.Root 打开的本地普通文件，在完成手机读取、长度/SHA-256 和同步后解析 .mp4/.mov/.m4v/.3gp/.3g2/.3gpp/.3gpp2。使用 io.ReaderAt 跳过 mdat 等负载，校验 32/64 位及延伸到父边界的 atom 长度；不依赖解码器或 FFmpeg，不遍历媒体字节。每文件总读取上限 2 MiB、最多 4096 个 atom、moov/udta 容器递归最多 8 层、最多 1024 个 metadata key、单个日期字符串最多 4096 字节。支持 mdta 的 com.apple.quicktime.creationdate UTF-8 日期、ilst/传统 udta 的 ©day，以及 mvhd v0/v1 的 1904 起算时间戳。优先明确日期元数据（video_metadata），其次电影头（container）；日期有效范围为 1970–9999，初始化日期/缺失时间回退修改日期或未知，损坏/超限记录非致命告警。显式时差保留日期原有年月，无时差字符串按 Mac 本地时区；mvhd 的 UTC 时间按 Mac 本地年月。元数据并不证明原始录制时间，也不推断未知拍摄地时区。未支持的容器不解析，仍按修改日期归档。归档不改视频创建日期、修改日期或内容。

`preview` 使用相同请求字段，`objectIDs` 必须只有一个支持预览的文件，`destination` 为应用创建的权限 0700 私有临时目录。校验存储、类型及隐藏设置，复用下载写入器的空间预检、长度检查、取消与无覆盖提交；返回 `completed.output` 为文件路径，不创建下载报告。应用仅在完整成功后把路径交给对应预览器，关闭、取消或正常退出时删除自有临时目录。错误事件也持续消费到 helper 退出，避免失败后立即重试与旧 USB 会话重叠；字节数、进度与终结事件字段不变。

`thumbnails` 的 `objectIDs` 限定 1–24 项，逐项返回 `thumbnail` 事件，新增 `objectID` 字段对应对象，`output` 为临时源文件路径，`state` 为 completed 或 unavailable，最后返回 completed。优先使用 MTP GetThumb；能力不支持、明确无缩略图、空数据，或完整 GetThumb 响应返回 GeneralError 时允许回退，不在 USB 传输错误后继续读会话。回退仅允许不超过 16 MiB 的图片，原图长度须吻合；视频不回退到完整读取，缩略图源文件同样限 16 MiB。文件信息或内容读取中完整 MTP 响应返回 GeneralError、InvalidObjectHandle、AccessDenied 时标为 ErrMediaObjectUnavailable，该缩略图以 unavailable 和 message 返回原因并继续其他对象；USB、同步、会话与身份/存储校验错误仍中止请求。常规下载遇到这些文件错误仍停止，不改变下载事务语义。全程不修改手机。

应用在本次连接中复用常驻串行 helper，减少重复会话开销，也避免系统接管反复捕获/归还设备。普通下载取消保留健康 helper；新连接、非下载请求的中断、错误、模式变更和断开会结束原 helper，等待清理后才能启动下一进程。多台手机接入时由用户选择一台，始终只有一个活动会话；不存在远程服务、HTTP API 或云端依赖。

`SIGINT`/`SIGTERM` 或常驻模式的 stdin EOF 触发上下文取消，USB 调用返回后停止；清理期间保留信号处理器，界面不把发送信号当成已完成取消。取消后 30 秒仍卡在原生调用/清理时兜底结束 helper，异常退出可能留下临时文件，驱动归还也可能需要用户重新插拔。应用退出时关闭管道并结束 helper，不安装后台服务。

## 下载事务

1. 遍历并校验所选对象，拒绝不安全路径、循环、非法大小；新保存方式保留同名对象，在实际创建/提交时编号解决冲突。
2. 汇总大小并预留 64 MiB；在目标的随机临时目录探测独占提交能力，exFAT 兼容路径额外预留最大单文件大小，均先于文件内容读取。
3. 默认直接使用用户指定目录，选择 `folder` 时另建批次目录。通过 Go `os.Root` 限制路径；报告与逐文件日志位于应用数据目录的独立任务目录。
4. 已知目标路径先检查同名冲突，明确跳过则直接记录，不读取手机内容或写入该文件的临时文件。其余文件在目标卷的随机隐藏任务目录中写入临时文件，检查取消、动态空间及实际长度，计算 SHA-256、同步并恢复有效修改时间；首次年月归档在此后解析日期确定路径。
5. 支持的卷通过 `renameatx_np(RENAME_EXCL)` 原子提交。父目录经 `os.Root` 打开，再以目录描述符和 basename 操作，不能从 Root.Name 拼绝对路径绕过限制。
6. 目标卷不支持独占重命名时，使用已确认的兼容路径：以 O_EXCL 创建最终文件，从已校验临时文件复制，再检查长度与 SHA-256、同步及恢复时间。此路径不保证最终名称在复制期间的原子可见性，正常取消/失败删除该次新建的未完成文件，不得因能力拒绝自动退化为覆盖式 rename；用户明确替换走已授权分支。
7. 新保存方式遇到目标文件已存在时，由界面确认保留两者、跳过或替换，未获明确替换授权不得覆盖；非交互客户端仍按既有编号策略处理。重试与回答不重读手机；普通源目录通过独占 Mkdir 另起编号目录并同步更新子项路径；归档生成年月目录可复用。未启用新选项的旧 CLI 仍拒绝同名。
8. 完成、失败或正常取消时更新报告、清理本任务临时目录并关闭资源；已完成文件保留。强制结束或拔盘可能残留临时文件或兼容复制中尚未完成的最终文件，不承诺自动恢复。

SHA-256 在本地写入过程中计算；不表示已与设备端内容摘要比对。支持同一 helper 内正常取消后的文件级继续，以及有持久化记录任务的退出/重启/重连后手动恢复；不支持文件内部续传、自动重试或跨任务去重。默认直接保存，按批次新建目录为可选项。任务页可查看独立保存的报告。

## 第三方依赖

Go 直接使用 `go-mtpfs/mtp`，不使用它的 FUSE 挂载层。第三方 C 依赖仅为动态链接的 libusb；照片日期处理使用 macOS 系统 ImageIO、CoreGraphics 和 CoreFoundation 框架。Swift 层无第三方包。libusb 从固定源码构建，并在 `.app/Contents/Frameworks` 打包；Go 引擎放在 `Contents/Helpers`。

Go 源码依赖以固定版本保存在 engine/vendor，构建显式使用 -mod=vendor。MTP 库的 Ferry 本地补丁仅从当前活动配置选择端点并优先标准 6/1/1 接口，打开后先核对配置，再检查 ClaimInterface 结果并激活所选 alternate setting；失败立即释放句柄，不带着未取得的接口发起 OpenSession。移除 claim 之后的 SetConfiguration，避免使已申请的端点失效；标准接口缺少可选名称时不拒绝，存在名称时保留校验。候选失败错误链向上传递，未选中的所有句柄与引用会释放，不能将接口申请失败吞成普通的无设备。普通初始化不调用 Configure 或新增 USB reset 恢复；移除 CloseSession 失败时的自动 Reset。用户允许系统接管时，helper 通过 libusb 的 DetachKernelDriver/AttachKernelDriver 对称捕获与归还整台设备，属于经批准的 USB 生命周期变更，可能影响照片导入或 ADB。当前 ad-hoc 本地包不添加 com.apple.vm.device-access，该受限制权限曾导致 AMFI 启动时 SIGKILL。EngineRunner 根据 helper 的签名元数据选择授权路径：有效签名且不含该 entitlement 的本地包使用一次性管理员认证，连接后永久降权；系统认可的非 ad-hoc 签名及相应授权配置可使用 entitlement 路径。实际许可由 macOS 判断，不能以 codesign 静态校验代替。界面程序没有该 entitlement。详见 [usb-access.md](usb-access.md)。

## 当前取舍

- 非根目录在设备支持时批量请求父对象、文件名、格式、大小、修改时间，按对象句柄合并并严格校验。根目录或同步的能力拒绝/完整但无效响应使用逐对象兼容读取；USB 超时和断开连接直接报错，不发布部分结果。
- 目录阶段显示中文阶段提示，兼容读取显示已处理数量；Swift 自然排序在后台任务执行，避免阻塞主界面。
- 不进行任何手机端写入；上传覆盖事务需单独设计。
- `USBDeviceMonitor` 通过 IOKit 监听 `IOUSBHostInterface`，仅读取注册表元数据；在主 RunLoop 枚举现有接口并接收接入/移除通知。通知标识来自设备位置、厂商、产品和可用序列号的摘要，每台手机的移除延迟 2 秒发布以容忍归还时的重新识别，多机接入时同样生效；请求仍按引擎指纹校验身份。
- `AutoConnectPolicy` 限制每次接入最多三次自动尝试，`AppModel` 对接入事件防抖并串行执行连接和目录读取。手动操作覆盖后台重试，授权拒绝停止重试；主动断开暂停监听，手动连接后恢复，演示模式关闭真实监听。
- 物理断开递增设备代次，旧请求不能重新填充目录；新设备的自动连接等当前 helper 完全退出后开始。关闭应用时取消定时任务、注销 IOKit 通知并关闭引擎。
- 下载默认直接保存，同名自动编号；批次目录为可选项，已有目录不合并，报告独立保存。
