# macOS USB 接口占用与临时接管

## 连接行为

“设置 → USB 连接”允许用户开启临时接管。普通连接不接管系统服务；若接口被其他进程独占，可能返回 `LIBUSB_ERROR_ACCESS`，不能据此断定手机未解锁或未选择文件传输。界面进程不加载 USB/MTP 原生库。

本地 ad-hoc 签名包不携带受限制的 `com.apple.vm.device-access` entitlement。该权限即使通过静态 codesign 校验，也可能在 main 执行前被 AMFI 拒绝。默认构建通过一次性的 macOS 管理员认证启动 USB helper，不安装 launchd 服务、不保存密码、不终止 `ptpcamerad`，也不更改系统保护。系统认证由用户完成。普通浏览和下载不需要在终端执行 sudo。

`EngineRunner` 只检查签名元数据。具有系统认可的非 ad-hoc 签名和设备访问 entitlement 的构建使用 `--usb-capture`，实际授权由 macOS 决定；有效签名但不含该 entitlement 的本地包使用 `--authorize`。携带受限制 entitlement 的 ad-hoc helper 不可用于授权连接。`Resources/ferry-engine.entitlements` 是后续签名流程的权限模板，默认构建不使用。

## 一次性管理员连接

未提权的 relay 在权限为 0700 的随机临时目录建立权限为 0600 的 Unix socket，再通过系统认证启动同一包内 helper。双方使用内核 `getpeereid` 验证对端 UID：relay 只接受 root，引擎核对发起用户。认证失败或取消返回 `authorization_denied`，停止当前接入的自动重试，可由用户手动重新连接。

提权引擎在 USB 初始化前核验本机通信对端。即使新会话由目录、大小或预览请求触发，也必须先完成连接并永久降权，才执行实际请求；这样取消缩略图后重建会话仍能继续浏览。只有对标准 6/1/1 或明确标识 MTP 的接口发现占用时才临时接管。libusb 接管整台设备，可能暂时影响所选手机的照片导入或 ADB。多台手机接入时由用户在左侧选择其中一台；引擎先按 USB 总线、端口路径和厂商/产品 ID 筛选，再打开唯一目标；有序列号时在 claim/接管前核验。未选择、无匹配或匹配不唯一时拒绝，不打开其他手机。未携带选择信息的旧请求仍不能接管多个候选设备。

连接成功后，通过系统账号查询取得发起用户附加组，依次设置附加组、GID 和 UID，永久退出 root；降权失败则停止请求并清理设备。在此之前不接受目录、预览或下载操作。所有下载路径、空间检查、临时文件与提交逻辑均以发起用户权限执行。

## USB 初始化与已有会话

仅从当前活动配置选择端点，核对配置并检查 claim 结果；claim 失败不进入 OpenSession，不在 claim 后重新设置配置。GET_INTERFACE 必须返回完整的 1 字节实际设置，仅在与目标 alternate setting 不同时调用 SET_INTERFACE。重复设置已生效的默认 0 可能重置端点状态，导致 OpenSession OUT 发送超时。

仅实际成功接管后、收到完整 `SessionAlreadyOpened` 响应时，关闭已有 MTP 会话并尝试重新打开一次。关闭失败、USB 超时、断开或协议同步错误均直接停止，不继续恢复。不使用会自动 Reset 的 `Configure`。

## 串行会话与释放

授权引擎通过非终结 `diagnostic` 事件传回 Go 日志，目录阶段耗时进入应用系统日志；这些事件不取代 `ready`，不触发 UI 请求完成。连接阶段另输出固定的 connection phase/state/result/elapsed_ms 标记，覆盖设备选择、OpenSession 与设备释放；结果不包含原始错误文本、文件路径或设备标识，Swift 以 public notice 记录，避免关键阶段被隐私遮蔽。release_device 的结果对应 Close 返回值，不单独证明手机的 CloseSession 已成功。

应用通过 `--serve` 复用一个串行 USB/MTP 会话。目录、缩略图、完整预览及下载串行执行；成功请求在终结事件后发送 `ready`，错误则结束引擎。直接 CLI 仍可使用单请求模式。

队列请求保留 `operation=download`，新增可选 `downloadID` 与 `downloadAction`。`begin` 完整规划、验证路径与空间后建立单个内存任务；`next` 最多提交一个完整文件，并可创建相邻目录；仍有文件时返回终结事件 `yielded` / `state=running`，随后发送 `ready`。目录读取可插在两个步骤之间；最后一步返回 `completed`。每条任务保持一个输出目录、一份报告和累计进度，始终无并发 USB 调用。逐文件循环由独立后台驱动执行，文件间交接不等待 MainActor；主线程只在会话准备和前台请求交还时参与。前台预留、请求认领、取消与引擎 epoch 捕获使用同一驱动锁，不在原生读取期间持锁。UI 通过最新快照邮箱接收合并的进度，generation、revision 和定时器编号分别丢弃旧请求、旧快照和旧倒计时。字节进度最多 4 Hz，任务摘要及控制操作及时发布，AppModel 不再转发每次字节、文件名或计时变化。未指定调度字段的请求继续一次完成全部下载。

协作下载可在完整文件已下载并同步后返回 `yielded / state=waiting` 与冲突 ID，再发送 ready，等待用户回答同名文件或月份目录选择。waiting 不持有活动 USB 调用或打开的文件句柄，仅保存已校验的完整本地临时文件；前台读取可继续在串行会话边界交错。`resolve` 需匹配当前任务、存储及冲突 ID，回答后无需重新读取该文件。默认保留原目标，仅用户明确选择 replace（或本次任务的相同策略）后允许原子替换本地普通文件，不改变手机只读约束。等待期间 cancel、EOF、断线和退出的正常收尾会清理该临时文件；UI 的过期回答不得触发新 helper。

`cancel` 只接受当前内存任务 ID 与原存储，返回 `completed` / `state=cancelled`，同一会话可继续浏览。取消活动下载不发送 SIGTERM、不调用 EngineRunner.cancel；先完整消费当前 begin/next/resolve 请求至 ready，再用同一 helper 发送 cancel，停止剩余文件并保留健康会话。大文件或规划阶段可能需要较长等待，最后一个文件已完成则按完成处理。取消后排队的新任务在取消请求与 ready 完成后开始，不重新打开 USB。取消等待期间若发生真实 USB/协议错误，不能当成普通取消后继续下一任务，必须报告错误并暂停后续队列。取消等待任务不请求 USB。目录请求等候文件结束时，停止目录只撤销读取；已有下载任务时，已开始的目录读取会排空响应并丢弃结果，不中断正在写入的文件。

正常取消仍可保留有界内存检查点并返回 resumeToken，所有文件句柄和临时文件按原流程清理。同一 helper 使用 resume/restart；跨退出或重连后的持久化任务使用 recover，用户必须先连接原手机并点击继续。EngineRunner 对这三种操作均禁止隐式启动 helper，不能因过期令牌或恢复记录触发重新连接、管理员授权或另一设备读取。恢复先验证设备指纹及稳定恢复标识（MTP 序列号，缺失时使用已选择 USB 目标序列号）和原存储，缺少稳定标识的手机只提供当前连接内继续。当前 USB 路由及存储 ID 可更新，原文件按完整路径重新定位并核验元数据；旧对象 ID 不直接用于跨连接读取。已完成文件仍只在本地进行长度/SHA-256 核验，每次 next 最多核验或读取一个文件，浏览和取消仍在文件边界串行执行。helper 退出清空内存令牌，独立恢复清单和逐文件日志保留，不从旧传输报告导入任务。

前台请求失败或 Swift 大小合并校验失败后，须清理旧 helper，禁止丢弃客户端任务 ID 却复用仍持有旧任务的引擎。断开、错误和 EOF 均收尾内存任务并保留已提交文件；待执行任务转为暂停，仅在原手机/模式/存储匹配时手动继续；具备持久化记录的失败任务保留恢复入口，仍不自动重跑或读取旧传输报告续传。下载队列期间禁止手机切换、模式切换和 USB 接管设置变更；完整预览与新缩略图暂停。

“断开连接”、更改接管设置、重新连接、请求错误、真正拔线或退出时结束会话；普通下载取消在文件边界处理，不结束健康会话。清理顺序为 CloseSession、ReleaseInterface、对实际接管的设备 AttachKernelDriver、关闭句柄。普通初始化或关闭失败不额外 Reset；接管/归还自身允许 libusb 重新识别设备。

关闭应用输入或 SIGINT/SIGTERM 会半关闭 relay 通道的写端，让引擎取消；读端继续等待清理完成，且等授权启动进程退出后才结束 relay。引擎输入与输出使用独立描述符，取消时不能提前关闭输出并误报归还完成。下一引擎等上一 relay 退出后才启动。

引擎原生调用持续卡住时保留取消后 30 秒的兜底退出；relay 额外等待至 45 秒。异常兜底不能保证归还完成，必要时重新插拔手机。等待系统认证最多 2 分钟。认证取消前后均不保存权限或安装后台服务。

USB 监听用位置、厂商、产品和可用序列号生成稳定通知标识；读取 IOKit 产品名供选择，名称相同时用 USB 路由区分。每台手机的移除延迟 2 秒发布，包括仍有其他手机连接时，避免接管期间短暂重新识别导致误断开；新增设备立即发布。请求的可选 `usbTarget` 包含 `busNumber`、`portNumbers`、`vendorID`、`productID`、`serialNumber`，浏览、大小读取、下载、预览和缩略图均携带同一目标，helper 重启也不能落到另一手机。`portNumbers` 使用 JSON 数字数组。请求仍用引擎指纹验证设备身份；活动会话不接受不同目标。切换目标先等待旧 helper 清理并清空目录、筛选、选择及媒体缓存。拔掉所选手机后不自动接管仍连接着的其他手机。主动断开会暂停监听，需手动连接，避免归还后立即接管回来。
